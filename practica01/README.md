# Hertz Rental Orders API

## Overview

A RESTful backend for registering Hertz vehicle rental orders. It stores customer, vehicle, plate, requested date, owned address and amount information in MySQL.

## Architecture Overview

The application follows the layered structure of the Learning Center Platform reference. The **Services** bounded context contains the business model; **Shared** contains common contracts, auditing and infrastructure.

- **Domain:** aggregates, value objects, commands and repository contracts.
- **Application:** creation use cases, result handling and context facades.
- **Infrastructure:** Entity Framework Core mappings, MySQL repositories and persistence components.
- **Interfaces:** REST controllers, input/output resources and assemblers.

## Key Features

- Rejects duplicate customer and vehicle combinations.
- Prevents a plate from being associated with different vehicle identifiers.
- Accepts the six vehicle identifiers defined by EVehicles.
- Requires a positive amount and a requested date that is not before the system date.
- Validates customer, plate and address lengths.
- Database-generated integer primary key.
- Automatic creation and update timestamps.
- Structured HTTP error responses and interactive Scalar documentation.

Error messages are provided in English.

## Getting Started

### Prerequisites

- .NET 10 SDK
- A running MySQL server
- The dotnet-ef tool compatible with EF Core 10

### Setup Instructions

1. Open `practica01.sln` or navigate to the project directory:

```powershell
cd .\practica01
```

2. Set your MySQL credentials in `appsettings.Development.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "server=localhost;port=3306;user=root;password=YOUR_PASSWORD;database=Hertz"
  }
}
```

3. Restore, build and apply the existing migrations:

```powershell
dotnet restore
dotnet build
dotnet ef database update --context AppDbContext
```

If this checkout has no migrations yet, generate the initial migration before updating the database:

```powershell
dotnet ef migrations add InitialCreate --context AppDbContext
```

4. Run the development HTTP profile:

```powershell
dotnet run --launch-profile http
```

5. Open [Scalar](http://localhost:5231/scalar/v1) or the [OpenAPI document](http://localhost:5231/openapi/v1.json).

## API Endpoint

```http
POST /api/v1/rental-orders
```

Creates a `RentalOrder`. The identifier is generated by the database and is not required in the request.

The response contains rentalOrderId, customer, vehiclesId, plate, requestedAt and address. Amount and audit timestamps are not exposed.

- **201 Created:** the record was saved successfully.
- **400 Bad Request:** request validation failed.
- **409 Conflict:** a uniqueness rule was violated.
- **500 Internal Server Error:** an unexpected server error occurred.

See `practica01/practica01.http` from the solution root for a sample request. No GET, update or delete operation is implemented.
